# voice-normal

Локальний інструмент для Windows 10/11, який робить із запису мови (камера, ноутбук,
запис екрана, петличка) чистий голос, як з подкастного мікрофона.
Працює як CLI і як Agent Skill для Claude Code / Codex. Усе обробляється на вашому
комп'ютері, нічого не відправляється в інтернет (крім одноразового завантаження моделей).

> Версія 0.1.0. Перевірено на Windows 11 (CPU) і в CI на windows-latest.

| Етап | Що | Стан |
|---|---|---|
| 1 | Каркас, `doctor`, обгортки, CI | готово |
| 2 | `install`: пакети й моделі | готово |
| 3 | `plan`: аналіз і маршрут | готово |
| 4 | `process`: відновлення і зведення | готово |
| 5 | Перевірка за гейтами, `report.md` | готово |
| 6 | Skill і плагін Claude Code / Codex | готово |
| 7 | Тести на зламаний вихід, документація | готово |

## Встановлення на Windows

Потрібно: Windows 10 або 11 (64-bit) і щонайменше 6 ГБ вільного місця
(≈1 ГБ пакетів, ≈1.5 ГБ моделей, решта — тимчасові файли під час обробки).
GPU NVIDIA не обов'язковий: без нього все працює на CPU, лише повільніше.

1. Встановіть інструменти (у PowerShell або cmd):

   ```powershell
   winget install Git.Git
   winget install Gyan.FFmpeg
   winget install astral-sh.uv
   ```

   Після встановлення відкрийте **новий** термінал, щоб оновився PATH.

2. Завантажте проєкт:

   ```powershell
   git clone https://github.com/volanderbo-stack/Voice-normal.git
   cd Voice-normal
   ```

3. Перевірте, що все готово:

   ```powershell
   .\voice-normal doctor
   ```

   Перший запуск сам поставить потрібний Python (3.12) — це займе хвилину.
   Пункти з `[!!]` треба виправити, `[..]` — це те, що зробить `voice-normal install`.

4. Встановіть ML-пакети й моделі (≈1 ГБ пакетів і ≈1.5 ГБ моделей, один раз):

   ```powershell
   .\voice-normal install
   ```

   Пристрій обирається сам: є NVIDIA — CUDA, немає — CPU. Можна задати явно:
   `--device cpu` або `--device cuda`. Якщо інтернет обірвався, просто запустіть
   `install` ще раз — завантаження продовжиться з місця зупинки. Кожен файл
   перевіряється за sha256; `install --verify` перераховує їх усі ще раз.
   Наприкінці `install` запускає кожну модель на тестовому сигналі й показує,
   у скільки разів швидше (або повільніше) за реальний час працює відновлення.

5. Подивіться, що в записі і як його оброблятимуть:

   ```powershell
   .\voice-normal plan "D:\Відео\запис з камери.mp4" --out cleaned\
   ```

   `plan` нічого не змінює у файлі. Він рахує гучність (EBU R128), де є мова,
   рівень шуму й SNR, кліпінг, смугу частот, реверберацію та оцінку DNSMOS.
   Далі обирає маршрут: «відновлення голосу» або «лише зведення», якщо запис уже
   чистий. Знаходить найважчі 150 с для проби і оцінює час обробки на вашому
   комп'ютері. Результат — `cleaned\<ім'я>.plan.md` (для людини) і
   `cleaned\<ім'я>.plan.json` (для `process` і агентів).

6. Обробіть запис:

   ```powershell
   .\voice-normal process "D:\Відео\запис з камери.mp4" --out cleaned\
   ```

   Що відбувається:
   - **План.** Береться готовий план із `cleaned\`, якщо він для того самого файлу,
     інакше аналіз іде заново.
   - **Проба.** Якщо запис довгий, спершу обробляються найважчі 150 с. Відновлення
     продовжується, лише якщо DNSMOS OVRL на них виріс. Інакше лишається тільки
     зведення, щоб не зіпсувати голос.
   - **Фрагменти.** Відновлення йде шматками ~30 с, які ріжуться в паузах між фразами.
     Зсув кожного шматка вимірюється й компенсується, тож звук лягає на відео.
   - **Тембр.** Повертається забарвлення голосу мовця: частково, не більше ±3 дБ і лише
     там, де оригінал не забитий шумом.
   - **Зведення.** −16 LUFS і true peak не вище −1 dBTP: загальне підсилення плюс
     лімітер, який торкається лише окремих піків. Компресора немає.

   Результат:
   - `cleaned\<ім'я>.cleaned.wav` — 48 кГц, 24 біти, моно, точно тієї самої довжини,
     що й оригінал;
   - для відео ще `cleaned\<ім'я>.cleaned.mp4` — відео скопійоване без перекодування,
     звук новий;
   - `cleaned\<ім'я>.report.md` — звіт перевірки (див. нижче);
   - `cleaned\<ім'я>.report.json` — ті самі дані повністю, для агентів і скриптів.

   На CPU (Intel i5 11-го покоління) хвилина запису обробляється приблизно
   за 1¾ хвилини: відновлення йде в реальному часі, решта — аналіз і перевірка.

### Як перевіряється результат

Після зведення результат порівнюється з оригіналом за вісьмома гейтами:

| Гейт | Що перевіряє | Не пройдено, якщо |
|---|---|---|
| Якість | DNSMOS SIG/BAK/OVRL до і після | OVRL упав більш ніж на 0.1 (або на 0.5 в будь-якому вікні 9 с) |
| Слова | Whisper small розшифровує оригінал і результат | розшифровки розходяться більш ніж на 15% або хоч одне слово чітко замінене іншим |
| Голос | схожість мовця (ECAPA) | нижче 0.45 загалом або 0.35 у вікні 10 с |
| Синхрон | зсув за початками звуків | більше 1 мс загалом або 20 мс у вікні 10 с |
| Гучність | ffmpeg EBU R128 по готовому файлу | далі ніж ±0.5 LU від −16 LUFS або true peak вище −1 dBTP |
| Шви | клацання і стрибок фону на межах фрагментів | клацання на 15 дБ гучніше сусідніх мілісекунд або фон стрибнув більш ніж на 5 дБ |
| Луна | затримана копія звуку (20–500 мс) | луни помітно більше, ніж в оригіналі |
| Довжина | кількість семплів, тривалість відео | не збігається точно (відео — ±0.05 с) |

Якщо щось не пройшло, до трьох раундів ремонту:

1. Гучність — звести ще раз із нижчою стелею.
2. Шов — перенести межу фрагментів в іншу паузу.
3. Слова, голос чи якість в окремому місці — переробити ці фрагменти з ширшим
   контекстом (3 с, потім 5 с).
4. Загальний зсув — зсунути весь результат на виміряну затримку.

Якщо й після цього відновлення не проходить, воно відкидається і лишається тільки
зведення оригіналу. Голос тоді не змінюється, а шум лишається. Звіт прямо про це
пише. Код виходу `1` означає, що якийсь гейт так і не пройшов: файл записано, але
його треба послухати.

Пороги підібрано на тестових записах: нормальний результат проходить їх із
запасом, а навмисно зіпсований — ні. Це перевіряють тести в `tests/test_broken.py`:
луна, зсув на 50 мс, +3 LU, підмінене слово, інший голос, клацання на шві, стрибок
фону. Гейти не замінюють прослуховування — послухайте хоча б початок, середину й кінець.

Мова повідомлень: `--lang uk` (за замовчуванням), `--lang ru` або `--lang en`,
або змінна середовища `VOICE_NORMAL_LANG`. Для агентів і скриптів є `--json`.

Якщо PowerShell не дає запускати `.ps1` (політика виконання), користуйтеся
`.\voice-normal.cmd doctor` — він робить те саме.

Дані й моделі зберігаються в `%LOCALAPPDATA%\voice-normal`. Щоб тримати їх деінде,
задайте змінну `VOICE_NORMAL_HOME`.

## Спробувати на демо-записі

**Справжній запис.** У [`docs/samples`](docs/samples) лежить хвилина пресконференції
NASA 1959 року: кілька голосів, зал, шум плівки. Поруч — результат обробки і звіт.
Запис є суспільним надбанням.

**Синтетичний.** Згенеруйте запис локально. Скрипт бере вбудований синтез
мови Windows і додає луну кімнати й шум вентилятора; нічого не завантажується:

```powershell
.\scripts\make-sample.ps1 -Video
.\voice-normal process samples\camera-sample.mp4 --out cleaned\
```

Порівняйте `samples\camera-sample.mp4` і `cleaned\camera-sample.cleaned.mp4`.
Цей самий сценарій щоразу проганяє CI на Windows, у папці з кирилицею й пробілами.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | готово; для `process` — усі гейти пройдено (можливо, із зауваженнями) |
| 1 | щось не так: гейт не пройшов навіть після ремонту, або файл не читається, або `doctor` знайшов проблему |
| 2 | неправильні аргументи або файл не знайдено |
| 3 | ще не виконано `voice-normal install` |
| 130 | перервано (Ctrl+C) |

## Якщо щось не працює

- **`uv`, `ffmpeg` або `ffprobe` не знайдено.** Встановіть через `winget` (крок 1)
  і відкрийте новий термінал. `doctor` підкаже точну команду.
- **PowerShell пише, що виконання сценаріїв вимкнено.** Користуйтеся
  `.\voice-normal.cmd` замість `.\voice-normal`. Політику виконання міняти не потрібно.
- **Обірвалося завантаження моделей.** Запустіть `install` ще раз — він докачає з
  місця зупинки. Пошкоджений файл покаже `install --verify`.
- **Дуже довгі шляхи (понад 260 символів).** Програма працює з ними сама (`\\?\`),
  але інші програми можуть ні. `doctor` показує, чи увімкнено LongPathsEnabled; вмикати
  його не обов'язково.
- **Мало місця.** `doctor` перевіряє вільне місце в папці даних (потрібно ≥ 3 ГБ,
  краще 6 ГБ). Під час обробки годинного запису тимчасові файли займають ще ~1 ГБ.
- **Обробка повільна.** На CPU хвилина запису — це приблизно 1¾ хвилини. З NVIDIA
  поставте `install --device cuda`.
- **Звіт каже «не пройдено».** Подивіться розділ «Де проблеми» в `report.md`: там час
  кожного проблемного місця. Файл записано, але слухати треба саме ці місця.

## Як усе прибрати

Видаліть дві папки:

- `%LOCALAPPDATA%\voice-normal` — моделі й налаштування;
- папку з клоном репозиторію, разом із `.venv`.

Якщо ставили skill, спершу виконайте `.\scripts\install-skill.ps1 -Uninstall`.
Ні в реєстрі, ні в системних налаштуваннях voice-normal нічого не лишає.

## Skill для Claude Code і Codex

Агент сам проходить усі кроки: `doctor` → (з вашого дозволу) `install` → `plan` →
`process`. Потім читає звіт і чесно каже, що пройшло, а що ні. Досить написати,
наприклад: «почисти звук у D:\Відео\камера.mp4».

**Варіант 1 — плагін Claude Code** (оновлюється командою `claude plugin update`):

```powershell
claude plugin marketplace add volanderbo-stack/Voice-normal
claude plugin install voice-normal@voice-normal
```

Або всередині сесії: `/plugin marketplace add volanderbo-stack/Voice-normal`.
Плагін — це окрема копія проєкту в кеші Claude Code, тож ML-пакети (≈1 ГБ) для неї
ставляться окремо, коли агент уперше запустить `install`. Моделі спільні:
вони лежать у `%LOCALAPPDATA%\voice-normal`.

**Варіант 2 — з клону репозиторію** (для Claude Code і Codex одночасно):

```powershell
.\scripts\install-skill.ps1
```

Скрипт створює junction (посилання на папку; права адміністратора й режим розробника
не потрібні) у двох місцях:

- `%USERPROFILE%\.claude\skills\voice-normal`
- `%USERPROFILE%\.agents\skills\voice-normal`

Після `git pull` skill оновлюється сам. Якщо junction створити не вдалося (мережевий
диск, синхронізована папка), скрипт копіює файли. Інші параметри:

- `-Agent claude` або `-Agent codex` — лише для одного агента;
- `-Mode copy` — завжди копіювати;
- `-Uninstall` — прибрати.

Чужу папку з такою самою назвою скрипт не перезапише. Реєстр, політику виконання
й змінні середовища він не чіпає. Якщо PowerShell не дає запустити скрипт, виконайте
`powershell -ExecutionPolicy Bypass -File .\scripts\install-skill.ps1` — це діє лише
на цей запуск. На macOS і Linux: `scripts/install-skill.sh`.

Після встановлення перезапустіть Claude Code або Codex.
